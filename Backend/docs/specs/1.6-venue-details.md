# 1.6 VenueDetails

Status: Done
Plan: [1.6 VenueDetails](../implementation-plan.md#16-venuedetails)
Depends on: 1.3 provider entity (done), 1.5 booking policy (done, same mapping pattern)

## Goal
A venue's facts that parents filter and decide by can be stored: how many children and adults fit, for which ages it is meant, whether outside food and cake may be brought, whether the venue serves food and whether it is included, whether it has its own animator or photographer, and whether there is a smoking area. 1.9 lets providers edit them, 1.11 shows them, 3.5 filters by capacity and age, and 5.3 checks an inquiry against them.

## Scope
- In: the `VenueDetails` value object, the `OutsideFoodRule` and `FoodService` enums and `VenueDetailsErrors` in `Domain/Venues/`; `Provider.VenueDetails` (null until set) and `Provider.ChangeVenueDetails`; the owned-type mapping on `providers`, check constraints, and the migration.
- Out: the command and endpoint that set the details (1.9); requiring them before review (1.13); showing them (1.11); search filters and any index they need (3.5); the capacity and age checks on an inquiry (5.3); prices of food, animators or photographers (1.15 offerings, 1.16 extras); `ServiceDetails` for catering and cakes (P2.11); animator and photographer as categories of their own (P3.0).

## Acceptance criteria
1. `VenueDetails.Create(maxChildren, maxAdults, minAge, maxAge, outsideCatering, outsideCake, foodService, hasOwnAnimator, hasOwnPhotographer, hasSmokingArea)` returns details with those values when they are valid.
2. `maxChildren` must be 1 to 500, else `VenueDetails.InvalidMaxChildren`.
3. `maxAdults` is optional (null: no separate limit for adults); when given it must be 0 to 500, else `VenueDetails.InvalidMaxAdults`.
4. `minAge` and `maxAge` are whole years from 0 to 18, else `VenueDetails.InvalidAge`; `minAge` greater than `maxAge` fails with `VenueDetails.InvalidAgeRange`. Both are inclusive; equal values are valid.
5. `OutsideFoodRule` is `NotAllowed`, `Allowed` or `AllowedWithFee`, used for both catering and cake; an undefined value fails with `VenueDetails.UnknownOutsideFoodRule`.
6. `FoodService` is `None` (the venue serves no food), `ForPurchase` (it sells food that isn't in the price) or `Included` (the price includes food for the children); an undefined value fails with `VenueDetails.UnknownFoodService`.
7. Two details with the same values are equal (record equality).
8. `Provider.Create` leaves `VenueDetails` null. `Provider.ChangeVenueDetails(details, utcNow)` sets it and `UpdatedAtUtc` on a `Venue` provider; on any other category it fails with `Providers.VenueDetailsNotForCategory` and changes nothing.
9. A provider saved with details is read back with equal details; one saved without is read back with null; replacing the details on a tracked provider is saved.
10. The database rejects a row with some details columns set but not all required ones, a row with `venue_min_age` greater than `venue_max_age`, and a row with details on a provider whose category isn't `Venue`.

## API
None.

## Data model
Nullable columns on `providers`, mapped as an owned type like `BookingPolicy`:
- `venue_max_children integer`, `venue_max_adults integer`, `venue_min_age integer`, `venue_max_age integer`.
- `venue_outside_catering varchar(20)`, `venue_outside_cake varchar(20)`, `venue_food_service varchar(20)` (enum names).
- `venue_has_own_animator boolean`, `venue_has_own_photographer boolean`, `venue_has_smoking_area boolean`.
- Check `ck_providers_venue_details_complete`: either all columns are null, or all except `venue_max_adults` are set.
- Check `ck_providers_venue_age_range`: `venue_min_age <= venue_max_age` when both are set.
- Check `ck_providers_venue_details_category`: details columns are null unless `category = 'Venue'`.
- Ranges stay in Domain only, as in 1.5. No index now; 3.5 adds one if search needs it.

## Edge cases
- `maxAdults = 0` is valid: parents drop the children off and adults don't stay.
- An age range of 0 to 18 means "any age"; a single age (6 to 6) is allowed.
- `Catering` and `Cakes` already exist in `ProviderCategory`, but nothing creates them until P2.11; they never get venue details. Changing a provider's category isn't possible; if it ever is, leaving `Venue` must clear the details, which the category check enforces.
- `AllowedWithFee` stores no amount: the fee is priced as an extra (1.16) or described in the text.

## Tests
- Unit (`VenueDetailsTests`): valid details with and without `maxAdults`; boundaries for each error in criteria 2–6 (0, 1, 500, 501 children; −1, 0, 500, 501 adults; −1, 0, 18, 19 years; min 7 and max 6 rejected, 6 and 6 accepted); an undefined rule for catering and for cake; an undefined food service; equality. `ProviderTests`: null after create; `ChangeVenueDetails` sets the details and `UpdatedAtUtc`; fails with `Catering` and `Cakes` and leaves the provider unchanged; throws on null.
- Integration (`ProviderPersistenceTests`): the round trip with and without details and with `maxAdults` null; replacing the details on a provider loaded tracked in a new scope; the three check constraints, by parameterized `ExecuteSqlAsync` updates of a saved row.

## Decisions
- **One value object on `Provider`, not a separate table or entity**: one set of details per venue, always loaded with it, the same pattern as `BookingPolicy`. P2.11 adds `ServiceDetails` the same way for the other categories.
- **The details are null until set**, like the booking policy: an admin-created profile shouldn't show parents numbers the venue never gave. 1.13 requires them before a venue goes to review.
- **The folder is `Domain/Venues/`**, so the namespace doesn't clash with the `VenueDetails` type.
- **One `OutsideFoodRule` enum for catering and cake**, since both questions have the same answers.
- **Animator and photographer are flags only**: whether the venue has its own. Whether they are included or cost extra belongs to offerings and extras (1.15, 1.16), which carry prices.
- **Smoking area is a flag**: a non-smoking venue is the default; parents only need to know whether adults can smoke somewhere.
- **A domain method `ChangeVenueDetails` comes now** so the round trip can be tested; 1.9 only adds the slice.

- **Capacity is a required maximum of children and an optional maximum of adults** (owner's answer): venues quote "do 30 dece" and the adults' space separately, and search filters by the number of children. No minimum here; the offering's minimum quantity (1.15) covers it.
- **Both ages are required, 0 to 18 whole years** (owner's answer): 18 reads as "no upper limit" on the page.
- **Food is a three-way `FoodService` choice, not a flag** (owner's answer): "the venue sells food but it isn't in the price" is common and matters when outside catering isn't allowed. What exactly is included is in the offering's included items (1.15).
- **Outside food is `NotAllowed`, `Allowed` or `AllowedWithFee`, without a fee amount** (owner's answer): a fee amount can come with 1.16 extras if venues ask for it.
- **The capacity limit is 500** (owner's answer): it only rejects typos and can change without a migration.

- **Found during the build:** the migration is `AddProviderVenueDetails`. The limits are the constants `VenueDetails.GuestLimit` and `VenueDetails.AgeLimit`, so they don't clash with the `MaxAge` property. The category check tests `venue_max_children` only: together with the complete check, that column being null means the whole set is null.
