# 1.4 Slug generation

Status: Done
Plan: [1.4 Slug generation](../implementation-plan.md#14-slug-generation)
Depends on: 1.3 provider entity (done)

## Goal
A provider's slug is generated from its name: transliterated to ASCII the way Serbian URLs are written, unique across all providers, and never a word the public URLs use for something else. The create handlers in 1.8 and 1.12 call it instead of taking a slug from the client.

## Scope
- In: `LookupSlug` renamed to `UrlSlug` (moved to `Domain/Slugs/`) with `FromName` added; `ProviderSlug` in `Domain/Providers/` (the reserved words and choosing a free slug); the reserved-word check in `Provider.Create` with `Providers.ReservedSlug`; `IProviderRepository.GetSlugsWithBaseAsync`; `IProviderSlugGenerator` and `ProviderSlugGenerator` in `Application/Providers/`, registered in `ApplicationConfiguration`.
- Out: calling the generator (1.8 admin create, 1.12 self-registration); changing the slug when a provider is renamed or moved (never done, see Decisions; 1.9 leaves it alone); generating city and district slugs when the admin adds districts (7.7, which can reuse `UrlSlug.FromName`); redirects from old slugs (not planned).

## Acceptance criteria
1. `UrlSlug.FromName` lowercases, transliterates Serbian Cyrillic to Latin (`љ`→`lj`, `њ`→`nj`, `џ`→`dž`, `ђ`→`đ`, `ћ`→`ć`, and so on), then writes `č ć`→`c`, `š`→`s`, `ž`→`z`, `đ`→`dj`, and strips any other diacritic (`é`, `ő`, `ü`) after Unicode compatibility decomposition (NFKD). `Рођенданска Журка` and `Rođendanska Žurka` both give `rodjendanska-zurka`.
2. The Russian letters that Serbian doesn't have are mapped too: `й`→`j`, `я`→`ja`, `ю`→`ju`, `ё`→`jo`, `ы`→`i`, `э`→`e`, `щ`→`sc`; `ъ` and `ь` are dropped.
3. Apostrophes (`'`, `’`) are dropped without a break (`Mike's` → `mikes`). Every other run of characters that isn't `a–z` or `0–9` becomes one hyphen, and leading and trailing hyphens are removed (`  Kids & Fun!! ` → `kids-fun`).
4. A slug longer than 60 characters is cut at the last hyphen at or before 60; a single word longer than 60 is cut at 60.
5. A name that leaves nothing (`★★★`) gives `profil`.
6. Every seeded city, district and amenity gets its seeded slug from its Serbian name.
7. `ProviderSlug.MakeUnique(baseSlug, takenSlugs)` returns the base when it is free, otherwise `<base>-2`, `<base>-3`, … the lowest free number. A reserved word (`kvart`) counts as taken. The suffix is added to the base as it is, so a slug with a suffix can be a few characters over 60 (still well within 100).
8. `Provider.Create` with a reserved slug fails with `Providers.ReservedSlug`.
9. `ProviderSlugGenerator.GenerateAsync(name, ct)` returns a slug that no saved provider has: with `kockica` saved it returns `kockica-2`; a saved `kockica-bar` or `kockicaa` doesn't make `kockica` taken.

## API
None.

## Data model
No change. `providers.slug` keeps its `varchar(100)` and unique index from 1.3.

## Edge cases
- Two creates with the same name at the same moment can both pick the same free slug; the unique index rejects the second save (see Decisions).
- `GetSlugsWithBaseAsync` filters with `slug = @base OR slug LIKE @base || '-%'`, which can't use the unique B-tree index. Fine for the expected few thousand providers; revisit if it shows up in slow-query logs.
- A Latin digraph written as one code point (`ǆ`, `ǉ`, `ǌ`) decomposes under NFKD and gives `dz`, `lj`, `nj`.
- Digits are kept (`Igraonica 123` → `igraonica-123`), so a name that is all digits gives an all-digit slug, which is valid.

## Tests
- Unit:
  - `UrlSlugTests`: criteria 1–5 as theories (Latin and Cyrillic forms of one name, each special Serbian letter upper- and lowercase, Russian letters, Hungarian accents, apostrophes, punctuation and space runs, digits, the 60-character cut at a hyphen and inside a long word, empty and all-symbol names); `IsValid` keeps its current cases after the rename.
  - `ProviderSlugTests`: free base; base taken; base and `-2` taken; `-2` free while `-3` is taken; `kvart` gives `kvart-2`; a 60-character base gets its suffix without being shortened.
  - `ProviderTests`: `kvart` fails with `Providers.ReservedSlug`.
- Integration:
  - `LookupSeedTests`: every row in `cities`, `districts` and `amenities` has `UrlSlug.FromName(name_sr) == slug` (criterion 6).
  - `ProviderSlugGeneratorTests`, through the DI-registered generator, with a unique base name per test because the tests share one database (`kockica` below): no providers gives `kockica`; saved `kockica` gives `kockica-2`; saved `kockica` and `kockica-2` give `kockica-3`; saved `kockica-bar` and `kockicaa` alone give `kockica`.

## Decisions
- **`LookupSlug` becomes `UrlSlug` in `Domain/Slugs/`**, because providers use it too now (1.3 left this to 1.4). It isn't called `Slug`: inside entities that name resolves to their `Slug` property.
- **Transliteration is hand-written, with no package.** The Serbian rules are a short table and must match the seeded slugs exactly (`đ`→`dj`, as in `rodjendaonice` and `arandjelovac`); all 215 seeded slugs already follow them.
- **Generation splits into pure Domain code and one Application service.** `UrlSlug.FromName` and `ProviderSlug.MakeUnique` are pure and unit-tested; `ProviderSlugGenerator` only loads the taken slugs through the repository (commands use repositories, not Dapper).
- **Reserved words live in `ProviderSlug.Reserved` and are checked in `Provider.Create`**, so a slug set any other way later can't take them either. The list is `kvart`, the only fixed word in the `/{category}/{city}/…` position of the public routes.
- **Generated slugs are at most 60 characters** for readable URLs; `UrlSlug.MaxLength` stays 100 for validation and the column.
- **Changed during the build: the suffix doesn't shorten the base.** A shortened candidate (`kockica-…-2` cut back to fit 60) isn't covered by the `base` / `base-%` lookup, so it could miss a taken slug. Adding the suffix as it is keeps the lookup exact; the result stays under 100.
- **The fallback is `profil`**, a neutral Serbian word, since the URLs are Serbian.
- **`&` and `+` are separators, not words** (`kids-fun`, not `kids-i-fun`): the same rule for every language a name may be written in.
- **A collision adds a number, not the city** (owner's answer): the URL already has the city, so `/rodjendaonice/beograd/kockica-beograd` would repeat it, and a third provider would still need a number.
- **The slug never changes after create** (owner's answer): shared links and search results keep working without a redirect table. A rename in 1.9 keeps it; an admin "regenerate slug" can come later if it's ever needed.
- **A race for the same slug isn't handled** (owner's answer): the unique index keeps the data right, the losing request gets a 500 and can be resent, and with admin creates and rare self-registrations it should practically never happen. 1.12 can add a retry if needed.
