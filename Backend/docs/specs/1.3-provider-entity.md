# 1.3 Provider entity

Status: Done
Plan: [1.3 Provider entity](../implementation-plan.md#13-provider-entity)
Depends on: 1.2 lookup data (done)

## Goal
A provider profile can be stored: its name, slug, category, description, address, city, district, location and phone, with a status and the times it was created, changed, claimed and suspended. The later Milestone 1 steps build their commands and queries on this entity.

## Scope
- In: the `Provider` entity and `ProviderErrors`, the `ProviderStatus` enum, the `PhoneNumber` value object and `PhoneErrors`, `IProviderRepository` and its implementation, the EF configuration, the `providers` table migration, and the `DbSet`.
- Out: generating slugs from names and checking that they're free (1.4); booking policy (1.5); venue details (1.6); amenities (1.7); any endpoint or command: admin create (1.8, which also limits the category to `Venue`), updates including the phone (1.9), self-registration (1.12); members (1.10); the public page, whether it shows the phone, and the visibility condition (1.11); status transitions, review notes, and the suspend and unsuspend methods (1.13); audit log (1.14); claiming (2.8); media (3.3); search indexes and the "recent activity" used in ranking (3.5, 3.7); optimistic concurrency for profile edits (1.9); development sample providers (1.11, when there's a page to show them); parents' phone verification (5.1, which may reuse `PhoneNumber`).

## Acceptance criteria
1. `Provider.Create` returns a provider with a new version-7 ID, status `Draft`, `CreatedAtUtc` and `UpdatedAtUtc` set to the given time, `ClaimedAtUtc` set to that time when it is created as claimed (null otherwise), and `SuspendedAtUtc` null.
2. The name and address are trimmed. An empty name fails with `Providers.NameRequired`, a name over 150 characters with `Providers.NameTooLong`; an empty address with `Providers.AddressRequired`, one over 200 with `Providers.AddressTooLong`. A description is optional (blank becomes null) and fails with `Providers.DescriptionTooLong` over 5,000 characters.
3. A slug that isn't lowercase letters and digits separated by hyphens (at most 100) fails with `Providers.InvalidSlug`. An undefined category fails with `Providers.UnknownCategory`.
4. A district from another city fails with `Providers.DistrictNotInCity`. No district in a city that has districts fails with `Providers.DistrictRequired`; no district in a city without any is valid.
5. The location is required, a Draft included. A location outside Serbia's bounding box (latitude 41.8–46.2, longitude 18.8–23.1, as the 1.2 seed test uses) fails with `Providers.LocationOutsideSerbia`.
6. The phone is optional. `PhoneNumber.Create` ignores spaces, hyphens, slashes, dots and parentheses, turns a leading `00` into `+` and a single leading `0` into `+381`, and stores the result in E.164 (`064/123-4567` → `+381641234567`). Anything that isn't then `+` and 8 to 15 digits, the first not `0`, fails with `Phones.InvalidNumber`.
7. A provider saved through `IProviderRepository.Insert` and `IUnitOfWork.SaveChangesAsync` is read back by `GetByIdAsync` with every field equal, the location and phone included.
8. The database rejects a second provider with the same slug, a city or district ID that doesn't exist, and deleting a city or district that a provider uses.
9. `providers.location` is `geography(Point, 4326)` with a GiST index, and `ST_DWithin` in meters finds a saved provider near its point and not one 10 km away.

## API
None.

## Data model
- `providers`: `id uuid` PK; `slug varchar(100)` unique; `name varchar(150) not null`; `category varchar(20) not null`; `description varchar(5000)` null; `address varchar(200) not null`; `city_id uuid not null` FK to `cities` (restrict); `district_id uuid` null FK to `districts` (restrict); `location geography(Point, 4326) not null` with a GiST index; `phone varchar(16)` null; `status varchar(20) not null`; `claimed_at_utc`, `suspended_at_utc timestamptz` null; `created_at_utc`, `updated_at_utc timestamptz not null`. Indexes on `city_id` and `district_id` (EF's FK indexes).

## Edge cases
- A city that gets its districts after providers there were created keeps them without a district. The rule is checked only when the place is set (create now, address changes in 1.9); 7.7 lists such providers when the city opens.
- Two providers may share an address, location and phone (two halls in one building); only the slug is unique.
- A foreign number (`+43…`) is accepted; only parents' numbers get a country allow-list (5.1).

## Tests
- Unit:
  - `ProviderTests`: a valid create (Draft, timestamps, claimed and unclaimed, not suspended, trimming, blank description to null, with and without a phone); each error in criteria 2–5, including the boundary lengths; a district from another city; a city with districts and no district; a city without districts and no district.
  - `PhoneNumberTests`: the Serbian local, `+381` and `00381` forms of one number give the same E.164 value; a foreign number; empty, letters, too short, too long and a `0` after the `+`.
- Integration (`ProviderPersistenceTests`, through the repository and a scoped `IUnitOfWork`): the round trip; duplicate slug, unknown city and unknown district (a unique or foreign key violation, with the constraint name); deleting a used city or district (a restrict violation, inside a transaction that is rolled back so seed data survives a missing key); the `ST_DWithin` check; the GiST index in `pg_indexes`.

## Decisions
- **`ProviderStatus` has `Draft`, `PendingReview`, `ChangesRequested` and `Published` now**, stored as its name in `varchar(20)` like `CityCategory`, so 1.11 can filter on `Published` before 1.13 adds the transitions. Only `Draft` is set in this step.
- **Suspension is a separate `SuspendedAtUtc`, not a status** (owner's answer), so unsuspending restores the review status without remembering it. The column comes now, so 1.11's visibility condition can include it; 1.13 adds the methods.
- **Claimed is `ClaimedAtUtc`, not a bool.** It answers "is it claimed" and "since when" in one column; the plan's "claimed flag" is `ClaimedAtUtc != null` (an `IsClaimed` property, not mapped).
- **Activity timestamps are `CreatedAtUtc`, `UpdatedAtUtc` and `ClaimedAtUtc`.** Domain methods set `UpdatedAtUtc` from the time they're given, as `City.OpenCategory` does; there are none yet besides `Create`.
- **The provider has a phone, and no email or website** (owner's answer). It's optional, because an unclaimed profile created by the admin may not have one; 1.13 can require it for review.
- **The phone is a `PhoneNumber` value object in Domain (`Phones/`), stored in E.164.** One normalized form keeps comparisons and later SMS or `tel:` links simple, and 5.1 can reuse it. It's mapped to `varchar(16)` with a value converter.
- **The district rule lives in `Provider.Create`**, which takes the city ID, the `District?` and whether the city has districts. Domain can't query, so the handlers in 1.8, 1.9 and 1.12 load the district and count the city's districts.
- **The slug format reuses `LookupSlug`.** 1.4 adds generation and may rename it to a shared `Slug`.
- **The location is required, a Draft included** (owner's answer), so search and the public page never handle a provider without a point; both create forms show a map. It comes from the client (a pin on the map): the architecture rules mention a future `IGeocoder`, but no plan step adds one. The bounding box catches swapped latitude and longitude, which `GeoCoordinate` alone accepts.
- **`description` is plain text as written** (no `LocalizedText`); translations are P2.13.
- **The `Venue`-only rule is not in the entity.** The domain accepts every category so P2.11 needs no domain change; 1.8 and 1.12 validators reject the others.
- **The repository has `GetByIdAsync` and `Insert` only.** Each later step adds what it needs (1.4 a slug lookup).
- **No search index beyond GiST and the FKs.** 3.5 adds the ones its queries need.
- **Found during the build:** the bounding box is Domain's `SerbiaBounds` (`Geography/`), next to `GeoCoordinate`, so 1.2's seed test and later steps can use the same numbers. The migration is `CreateProvidersTable`.
- **Found during the build:** Postgres reports deleting a referenced city or district as a restrict violation (`23001`), not a foreign key violation (`23503`); the tests check for that.
